# Data

## responses.json

Generated by `scripts/1_generate_data.py`. The original 75-response dataset (15 prompts per topic).

Run `python scripts/1_generate_data.py` from the project root to regenerate it. Requires a Groq API key (see main README for setup).

### Format

Each entry:
```json
{
  "topic": "poetry",
  "prompt_index": 3,
  "prompt": "What makes a poem different from other forms of writing?",
  "token_lengths": [14, 8, 10, 5, 12, 9, 7, 3, ...]
}
```

## prompts_candidate_100.json

Generated by `scripts/5_build_prompts_no_api.py`. A pool of 100 prompts per topic (the original 15 plus 85 new ones, built mechanically from sub-aspect x question-frame combinations, zero API cost) used as the input for the 500-response scale-up.

## responses_100.json

Generated by `scripts/6_collect_responses_100.py` from `prompts_candidate_100.json`. Same format as `responses.json` above, 500 responses total (100 per topic across 5 topics). This is what `scripts/2_train_evaluate.py` runs on for the 500-response results in the main README.

Collection is resumable: if the script crashes or hits a Groq rate limit mid-run, re-running it skips already-collected responses.

## generation_log.txt

Captured terminal output from running `scripts/1_generate_data.py`. Shows the actual prompts sent, the chunk count returned per response, and the per-topic sanity check averages (poetry ~555 chunks, python_code ~616, medical ~621, cooking ~592, legal ~522). Kept as evidence of what the original 75-response data collection run actually produced.

## reponses_gemini_2.txt / responses_gemini_catched.txt

Real-traffic captures of Gemini conversations used for Bonus 1. `scripts/normalization.py` log-scales the raw packet sizes here into the same [1, 50] range as the API-based chunk lengths, so the real-traffic distributions are comparable to the simulated ones. Feeds into the analysis in `results/bonus_1/`.
